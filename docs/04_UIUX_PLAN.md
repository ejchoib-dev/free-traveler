## 1. 목적

이 문서는 `03_UI_COVERAGE_ANALYSIS.md`에서 화면별로 배치한 요구사항을 실제 레이아웃·컴포넌트·상태로 구체화한다. Airbnb 참고본은 "흰 캔버스 + 단일 포인트 컬러 + 부드러운 라운드 + 얕은 그림자 1단계 + 카드 밀도 대비 여백" 같은 **구조적 패턴**만 참고하며, Rausch 색상, Cereal 서체, 3-프로덕트 내비게이션, 하트/게스트favorite 배지 같은 **Airbnb 고유 상표·아이덴티티 요소는 사용하지 않는다.**

## 2. 브랜드와 디자인 원칙

| 원칙 | 내용 |
|---|---|
| 브랜드명 | Free Traveler |
| 톤 | 신뢰할 수 있는 여행 정보 허브 — 화려한 마케팅보다 정보의 명확성과 안전 고지를 우선한다 |
| 색 | 흰 배경, 짙은 회색 텍스트, 코랄 포인트 컬러 1가지만 반복 사용(과다 사용 금지) |
| 서체 | 한글 본문은 Inter + 시스템 한글 폰트 fallback(Inter는 한글 글리프가 없어 한글은 자동으로 fallback 폰트로 렌더링됨) |
| 형태 | 부드러운 라운드(카드 12px, 버튼 10px, Chip은 완전 라운드), 그림자는 1단계만 사용 |
| 접근성 | 키보드 포커스 링 상시 대비, 터치 영역 44×44px 이상 |
| 안전 신호 | 오류·경고·안전정보는 코랄과 명확히 구분되는 semantic color 사용(코랄=행동 유도, 세만틱 컬러=상태/경고) |

| 토큰 | 값 |
|---|---|
| `space.xxs~xxl` | 2 / 4 / 8 / 12 / 16 / 24 / 32 / 48px |
| `space.section-desktop` | 64~96px (Section 성격에 따라 선택: Hero 64px, 표준 Section 80px, CTA Banner 96px) |

| `shadow.card` | `0 1px 2px rgba(20,20,20,.04), 0 4px 12px rgba(20,20,20,.08)` — 카드 hover, Drawer, 드롭다운에만 사용하는 유일한 그림자 단계 |

### 3.4 Breakpoint 기준

| 기준 | 폭 | 비고 |
|---|---|---|
| **Desktop 기준** | **1440px** | 콘텐츠는 `container-max`(1200~1280px)로 중앙 정렬, 좌우 여백이 나머지를 흡수 |
| Tablet(전환 구간) | 744~1128px | Card Grid 열 수를 3→2로, 좌우 분할 비율을 유지하되 폭만 축소 |
| **Mobile 기준** | **390px** | Card 1열, Section 여백 축소, Drawer는 하단 시트로 전환 |

### 3.5 접근성 규칙

- 모든 인터랙티브 요소는 **44×44px 이상**의 터치 영역을 갖는다(버튼, 아이콘 버튼, 탭, Chip 포함).
- 키보드 포커스는 `:focus-visible`에서 `2px solid color.primary` + 2px offset 아웃라인으로 표시하며, 마우스 클릭 시에는 표시하지 않는다.
- 모든 이미지에는 실제 장소·상황을 설명하는 대체텍스트를 붙인다(예: "제주 성산일출봉 앞 유채꽃밭").
- 상태(경고/오류/중대경보)는 색상과 텍스트 라벨을 항상 함께 표시한다.

## 5. 레이아웃 패턴 정의

같은 Card 패턴만 반복하지 않기 위해 아래 6개 패턴과 2개 보조 패턴을 화면별로 교차 사용한다.

| 패턴 | 설명 |
|---|---|
| Hero | 제목+설명+핵심 CTA/검색, 화면 전체 높이를 차지하지 않음(Desktop 최대 520px) |
| Card Grid | Desktop 3~4열, Tablet 2열, Mobile 1열 카드 나열 |
| 좌우 분할 | Desktop 좌/우 두 블록(예: 40/60), Mobile은 세로 스택 |
| Chip 목록 | 가로 스크롤 또는 wrap되는 pill 형태 선택지 |
| 3단계 안내 | 번호가 매겨진 3개 스텝 카드(가로 배열 Desktop, 세로 배열 Mobile) |
| CTA Banner | 배경이 구분되는 밴드 안에 설명+버튼(들) |
| Timeline(SCR-002 전용 보조) | 세로 타임라인, 연도-장소-요약 반복 |
| Gallery(SCR-002 전용 보조) | 사진 중심 그리드, 텍스트 최소화 |

## 6. 화면별 상세 설계

### 6.1 SCR-001 `/` 메인

**사용자 목표**: 여행지를 발견하고 상세·안전정보를 확인한 뒤 `/travel-tools`, `/mates`, `/about`으로 자연스럽게 이동한다.

| # | Section | 패턴 | 제목 | 설명(요약) | 콘텐츠/CTA |
|---|---|---|---|---|---|
| 1 | 검색 Hero | Hero | 어디로 떠나고 싶으신가요? | 국내외 인기 여행지를 검색하고, 항공·숙소 조건을 정리한 뒤 안전하게 이동을 준비하세요. | 목적지·테마 키워드 검색창(REQ-FUNC-003) + 보조 버튼 "여행 준비 시작하기" → `/travel-tools` |

| 6 | 동행 미리보기 | 좌우 분할 | 함께 떠날 동행을 찾아보세요 | 만 19세 이상 인증 회원이 국가·기간·스타일이 맞는 동행을 찾고 참가를 요청할 수 있습니다. | 좌: 설명+CTA "동행 전체 보기"(`/mates`) / 우: 최근 동행글 카드 3개(Success) 또는 Empty 안내(§7 참고) |

**Drawer 규격**
- 여행지 상세 Drawer: Desktop 우측 슬라이드 폭 520px, Mobile 하단 시트 높이 92%. 내부에 REQ-FUNC-004 필수 항목(소개/명소/시기/일정/예산/교통/음식/에티켓/출처)을 순서대로 배치하고, 해외 여행지는 하단에 "국가 안전정보 보기" 버튼으로 안전정보 Drawer를 이어서 연다(같은 슬라이드 스택 위에 열림).
- 안전정보 Drawer: 8개 카테고리 섹션 + 출처·확인일 + stale 경고 배지 + 외교부 링크(새 탭) + 중대경보 시 상단 고정 배너.

**Hero 높이 규칙**: Desktop 1440×900 기준 Hero 최대 높이 520px로 제한해, 스크롤 없이도 Section 2 상단 카드 일부가 노출되게 한다.

## 8. Requirement 반영 확인

- `03_UI_COVERAGE_ANALYSIS.md`에서 SCR-001~005에 배치된 UI_DIRECT/UI_STATE 요구사항은 위 Section 표에 모두 위치를 부여했다(여행지·안전 상세→SCR-001 Drawer/Modal, 항공·숙소·동행작성→SCR-003 3탭, 동행 상세→SCR-004 상세 패널, 로그인·프로필·내 활동·관리자→SCR-005 탭).
- `PROJECT_SCOPE.md`에서 EXCLUDED로 확정한 기능(전체 콘텐츠 CMS, 미디어 라이선스 워크플로, 통합검색, 링크 공유, 관련 여행지 자동 추천, 감사 로그, 안전정보 stale 대시보드, 계정 제재 도구 등)은 이번 화면 설계에 포함하지 않았다.
- API Route, 인증 콜백, 404/500 오류 화면은 기술 Route로 유지하며 5개 디자인 Screen 어디에도 6번째 화면으로 추가하지 않았다.
